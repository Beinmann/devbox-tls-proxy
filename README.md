# devbox-tls-proxy

A Docker container that terminates TLS for `https://localhost.rdrkolaq.de`
and passes **all** requests (websockets included) unchanged to **one named
container** on the Docker network `devbox-net`. Use it when a browser needs a
real, trusted HTTPS origin (secure-context APIs, OAuth redirects, ...) for a
dev server in a container. Sister repo to `devbox-proxy` (same network, same
style).

It is [Caddy](https://caddyserver.com) built with the `caddy-dns/cloudflare`
plugin. The certificate is a real Let's Encrypt certificate obtained through
the DNS-01 challenge via the Cloudflare API, so nothing has to be reachable
from the internet, and `localhost.rdrkolaq.de` can simply resolve to
`127.0.0.1`. No auth layer: the port is bound to loopback only.

## Quickstart

    cp .env.example .env          # set CF_API_TOKEN (see Cloudflare setup)
    ./start.sh my-devbox          # proxies https://localhost.rdrkolaq.de -> my-devbox:80
    ./start.sh my-devbox --ports 443:3000,5173,8000-8010
    ./stop.sh my-devbox

The first start builds the image and requests the certificate (about a
minute; watch `docker logs -f devbox-tls-my-devbox`). `./start.sh ... --dry-run`
prints the docker commands (token redacted) without running anything.

## Configuration

Set in `.env` (gitignored) or the environment; `--ports` and the positional
container argument override `PORTS` / `TARGET`; real environment variables
override `.env`.

| Variable | Default | Meaning |
|---|---|---|
| `TARGET` | (required) | Name of the container to proxy to (first argument of `start.sh`) |
| `CF_API_TOKEN` | (required) | Cloudflare token, Zone:DNS:Edit on `rdrkolaq.de` |
| `PORTS` | `443:80` | Comma list. `N` = listen N -> target N; `L:T` = listen L -> target T; `A-B` ranges expand (each N -> N); `A-B:C-D` pairs equal-length ranges. Example: `443:3000,5173,8000-8010` |
| `DOMAIN` | `localhost.rdrkolaq.de` | Host name served |
| `ACME_CA` | Let's Encrypt | ACME directory URL override, e.g. `https://acme-staging-v02.api.letsencrypt.org/directory` for testing (staging certs are not browser-trusted) |
| `HOST_HEADER` | `original` | `original`: the `Host` header reaches the app unchanged (`localhost.rdrkolaq.de:443`), also `X-Forwarded-*` are added by Caddy. `target`: send `Host: <TARGET>:<port>`, for apps/dev servers that reject unknown hosts (e.g. Vite `allowedHosts`) |
| `DOCKER` | `docker` | Docker command, e.g. `sudo docker` |

Each listen port gets its own site block (`<DOMAIN>:<L>`), generated by
`gen-caddyfile.sh` (runnable without Docker/Caddy: `TARGET=x CF_API_TOKEN=y
./gen-caddyfile.sh`). Proxying uses `flush_interval -1` (no response
buffering: SSE/streaming) and Caddy's native websocket support. Invalid
`PORTS`, duplicate listen ports and missing `TARGET` / `CF_API_TOKEN` fail
immediately with a message.

The container is `devbox-tls-<target>`, on `devbox-net` (created if missing),
publishing `127.0.0.1:<L>:<L>` per listen port.

## Several containers

Only one proxy can bind a given host port. Give each additional container its
own listen port:

    ./start.sh devbox-a                      # https://localhost.rdrkolaq.de
    ./start.sh devbox-b --ports 8443:80      # https://localhost.rdrkolaq.de:8443

All instances share the named Docker volume `devbox-tls-certs` (mounted at
Caddy's `/data`), so the certificate is issued once and reused, which keeps
you well within Let's Encrypt rate limits. `stop.sh` keeps the volume.

## Cloudflare setup (once, manual)

**API token.** Cloudflare dashboard -> My Profile -> API Tokens -> Create
Token -> "Create Custom Token". Permissions: `Zone` / `DNS` / `Edit`. Zone
Resources: Include -> Specific zone -> `rdrkolaq.de`. Create, copy the token
into `.env` as `CF_API_TOKEN`. (Some plugin versions also want `Zone / Zone /
Read`; add it if the logs complain about listing zones.)

**DNS record.** Dashboard: DNS -> Records -> Add record: type `A`, name
`localhost`, IPv4 `127.0.0.1`, proxy status **DNS only** (grey cloud; a
proxied record cannot point to a loopback address). Or via API:

    curl -X POST "https://api.cloudflare.com/client/v4/zones/<ZONE_ID>/dns_records" \
      -H "Authorization: Bearer <API_TOKEN>" \
      -H "Content-Type: application/json" \
      --data '{"type":"A","name":"localhost.rdrkolaq.de","content":"127.0.0.1","ttl":300,"proxied":false}'

The zone id is on the zone's Overview page (right sidebar), or
`curl -H "Authorization: Bearer <API_TOKEN>" "https://api.cloudflare.com/client/v4/zones?name=rdrkolaq.de"`
(this lookup needs a token that may read zones).

**DNS rebind protection.** Some routers / resolvers (dnsmasq `stop-dns-rebind`,
FritzBox, Pi-hole, corporate DNS) drop answers pointing at private/loopback
addresses, so the name does not resolve. Fallback: add to `/etc/hosts`
(on Windows, `C:\Windows\System32\drivers\etc\hosts`, if the browser runs there):

    127.0.0.1 localhost.rdrkolaq.de

## Security notes

- Published on `127.0.0.1` only. Anyone with access to the machine (any local
  user or process, anything that can reach loopback) reaches the target
  container through this proxy with no authentication.
- `CF_API_TOKEN` can edit DNS of the zone: keep `.env` private (it is
  gitignored), scope the token to the one zone. `start.sh` hands it to Docker
  via an env-file on stdin, so it is not in the process list or printed;
  it is still visible to anyone who can `docker inspect` the container.
- The proxy forwards to exactly one container (`TARGET`), not to arbitrary
  hosts. Only the target ports you list in `PORTS` are exposed.
- The admin API of Caddy is disabled.

## Tests

    tests/run.sh      # plain bash, no Docker or Caddy needed (runs shellcheck if installed)

Covers port parsing, generated Caddyfiles, failure modes and `start.sh --dry-run`.
The image build, certificate issuance and live proxying are not covered by
automated tests.
